# Google 미인증 안내 해소를 위한 검토 준비

현재 지원 이메일은 **bokmunssu@gmail.com**, Google 프로젝트는 **firm-buffer-488015-s0**입니다. 본인 소유 도메인은 아직 없습니다. **인증 신청·검토 승인·미인증 경고 해제는 아직 완료되지 않았습니다.** 운영자 화면에서 체크 한 번으로 ‘신뢰 가능한 앱’이 되는 방식이 아닙니다.

## 이 변경에서 준비한 것

- TOMO 홈페이지(`docs/index.html`), 개인정보처리방침(`docs/privacy-policy.html`), 이용 안내(`docs/terms-of-service.html`)와 지원 연락처를 작성했습니다. 기존 SHINYA의 사이트·연락처·다운로드 링크·도메인 설정은 교체/제거했습니다. 아직 사이트를 게시하거나 승인된 도메인이라고 표시하지 않습니다.
- 전체 `calendar` 권한을 제거하고 필요한 `calendar.events`, `calendar.calendarlist.readonly`, `calendar.app.created` 및 `userinfo.email`, `openid`로 좁혔습니다. 캘린더 ACL/공유 권한 관리나 Gmail/Drive 권한은 요청하지 않습니다. 새 권한으로 재로그인과 실제 API 동작은 검토 신청 전에 확인해야 합니다. 기존 토큰은 자동 폐기하지 않습니다.
- 일반 사용자의 개인 API 입력 화면을 제거했습니다. 배포자가 설정한 OAuth 클라이언트를 공통으로 쓰고 사용자는 각자 로그인합니다. 빈 사용자 데이터 폴더의 빌드 설정·로그인 활성화를 테스트하지만 타인 계정의 실제 동의까지 성공했다고 간주하지 않습니다.

## 도메인이 없을 때

Google은 홈페이지/개인정보처리방침 도메인의 소유권 확인을 요구합니다. 소유권을 증명할 수 없는 제3자 플랫폼의 경로는 승인용 홈페이지로 적합하지 않습니다. 단순 GitHub 저장소 링크나 Google Sites로 요건을 충족한다고 보장하지 않습니다. 무료 서브도메인을 이용하더라도 Search Console 소유권 확인과 OAuth 검토자의 수락 여부가 필요합니다.

현재는 비용 없이 준비 파일을 검토하고 Testing 사용자를 추가해 제한적으로 사용할 수 있습니다. **이 경로는 미인증 경고를 제거하지 않습니다.** 소유권 확인 가능한 도메인을 마련하면 정적 사이트는 무료 호스팅에 올릴 수 있지만 도메인 자체 비용은 별개입니다. 유료 도메인 구입·Azure 구독·Microsoft Store 배포는 이 작업에서 진행하지 않습니다.

## 도메인이 준비된 후 실제 신청 순서

1. 위 세 페이지를 같은 HTTPS 도메인에 게시합니다. 로그인 없이 열려야 하고 TOMO 앱 기능·운영자·실제 데이터 사용을 정확히 설명해야 합니다. 아직 미인증이라는 홈페이지 안내는 실제 검토 승인 이후에만 수정합니다.
2. 지원 이메일을 사용하는 계정으로 Search Console에서 도메인 소유권을 확인합니다. DNS TXT를 쓸 수 있으면 도메인 속성을 사용합니다. 호스팅/서브도메인의 확인 가능성과 승인 가능성을 먼저 확인합니다.
3. Google Auth Platform → Branding에 앱 이름 TOMO CALENDAR, 지원/개발자 이메일, 홈페이지·개인정보처리방침·이용 안내 URL, 해당 도메인을 입력합니다. 원본 제작자 도메인을 넣지 않습니다.
4. Data Access에 코드가 실제 요청하는 권한을 등록하고 사용하지 않는 권한을 제거합니다. 아래 권한 설명을 사용합니다. 토큰 갱신과 사용자 거부 상황도 검사합니다.
5. 데스크톱 OAuth 클라이언트를 유지하고 Google Calendar API 사용 설정을 확인합니다. 웹 클라이언트·서비스 계정으로 바꾸지 않습니다. 개발 테스트와 공개 배포용 프로젝트 분리를 검토합니다.
6. 서로 다른 개인 계정으로 로그인→동의→캘린더 선택→시험 일정 가져오기/수정/업로드→연결 해제를 확인합니다. 소수 공유 중 Testing 계정은 운영자가 테스트 사용자에 추가해야 합니다.
7. 데모 영상을 준비합니다. 처음 실행, Google 동의 화면(앱 이름/클라이언트/각 권한), 캘린더 선택, 각 권한이 사용되는 기능과 해제를 끊김 없이 보여주세요. 사용자 데이터·토큰을 노출하지 않는 시험 계정을 사용합니다. 실제 영상이 있어야 하며 문서만으로 대체하지 않습니다.
8. Audience 공개 상태와 Verification Center의 Brand/Data Access 검토 요청을 콘솔 안내에 따라 제출합니다. Production 전환과 검증 완료는 별개입니다. 추가 질문/보완 요청은 지원 이메일로 받아 답변합니다. 검토 기간·승인을 보장하지 않습니다.
9. 승인 후 새 개인 계정으로 미인증 안내가 사라졌는지, 해당 클라이언트/권한이 승인 범위와 같은지 다시 확인합니다. 변경된 권한·브랜드·도메인은 재검토가 필요할 수 있습니다.

## 검토 양식에 사용할 권한 설명

| 권한 | 실제 기능과 필요 이유 |
| --- | --- |
| `calendar.events` | 사용자가 선택한 기존 캘린더의 일정 제목·시간·반복을 TOMO에서 표시하고 편집 내용을 양방향 동기화합니다. 읽기 전용 권한으로는 사용자가 요청한 생성·수정·삭제를 반영할 수 없습니다. 사용자의 계정 ACL이 허용한 범위를 넘지 않습니다. |
| `calendar.calendarlist.readonly` | 구독한 캘린더의 이름·색·식별자를 보여주어 사용자가 가져올 대상을 선택하게 합니다. 구독 목록 수정이나 공유 권한 관리는 하지 않습니다. |
| `tasks` | Google Tasks 로그인에서 선택한 목록의 할 일 제목·기한·완료·삭제를 양방향 동기화합니다. Calendar 로그인에는 이 범위를 추가하지 않습니다. |
| `calendar.app.created` | 사용자가 TOMO용 보조 캘린더 생성을 선택하면 생성하고 그 캘린더의 일정에 접근합니다. 임의의 기존 캘린더 전체 속성/공유 권한을 관리하는 범위를 요청하지 않습니다. |
| `userinfo.email`, `openid` | 로그인한 Google 계정을 식별하고 연동 창에 계정 이메일을 표시합니다. 다른 계정의 정보를 요청하지 않습니다. |

일정 데이터는 선택한 동기화 기능을 위해 기기와 Google API 사이에서 사용합니다. 판매·광고 타기팅·범용 AI 학습에 사용하지 않으며 유지보수자 서버로 자동 전송하지 않습니다. 개인정보처리방침에는 로컬 보관·삭제·해제·외부 API·업데이트 요청을 명시했습니다. 이 사실관계를 실제 프로그램 동작과 다시 비교한 뒤 제출하세요.
