# TOMO CALENDAR 보안 범위

## 2.3.3에서 적용한 보호

Google Calendar 인증 토큰은 Electron 메인 프로세스의 OS 암호화 저장소에 보관합니다. 로그인·연결 상태 API는 토큰을 반환하지 않습니다. 화면은 구글 API 요청을 직접 보내지 않고 메인 프로세스에 허용된 작업을 요청합니다. 오래된 화면 저장소의 `googleCalendarAuth` 항목은 제거하지만 기존 암호화 계정·메모·일정은 유지합니다.

구글 요청은 고정 HTTPS 호스트와 허용된 캘린더 경로·HTTP 메서드·검색 매개변수만 사용합니다. 리다이렉트로 인증 정보를 다른 호스트에 전달하지 않으며 요청 시간은 20초로 제한합니다. 캘린더는 동시 요청 16개·분당 요청 600개를 제한하고 403/429 응답 후 1분 대기합니다. 이 로컬 제한은 수정된 앱이나 다른 PC의 요청을 통제하지 못하므로 Cloud 프로젝트 한도를 대신할 수 없습니다.

모든 내부 기능 요청은 앱이 소유한 창의 최상위 프레임과 배포된 `dist/index.html` 주소인지 확인합니다. 외부 파일·웹페이지·하위 프레임의 요청을 거부합니다. 본체와 위젯에서 외부 페이지 이동·새 창·웹뷰 부착을 막습니다. 외부 링크는 자격증명과 별도 포트가 없는 `https://github.com` 및 `https://tasks.google.com`으로 제한합니다. 시스템 브라우저를 이용한 Google OAuth는 별도의 고정 주소를 사용합니다.

배포 HTML에 CSP를 적용해 외부/인라인 스크립트와 프레임·객체를 차단합니다. 테마에 필요한 인라인 스타일, 로컬 이미지와 폰트는 허용합니다. 개발 서버에서는 Vite의 개발 기능을 위해 해당 HTML 정책만 제외하며 내부 호출의 주소 검증은 유지합니다. 개발 서버를 인터넷에 공개해서는 안 됩니다.

Electron 44.5.1, electron-updater 6.8.9, Swiper 14.3.0과 보안 패치가 적용된 관련 의존성으로 갱신합니다. 잠금 파일을 사용해야 검사한 버전으로 설치됩니다. 취약점 데이터는 계속 변경되므로 다음 배포에서도 검사를 반복해야 합니다.

## 남아 있는 제한

- 실행파일은 전자서명되지 않았습니다. 업데이트의 SHA-512 검사는 파일과 매니페스트를 동시에 바꾸는 공격을 막지 못합니다. GitHub 계정·릴리즈 게시 권한·배포 워크플로를 보호해야 합니다. 이 업데이트에서 인증서 구매나 Microsoft Store 배포를 요구하지 않습니다.
- 일정·메모·이미지는 로컬에 암호화 없이 저장합니다. 같은 Windows 계정의 악성 프로그램이나 유출된 백업으로부터 내용을 보호하지는 못합니다. OS 암호화 토큰 저장도 이미 장악된 PC 전체를 보호하는 수단은 아닙니다.
- 데스크톱 OAuth 등록 정보는 배포본에서 추출할 수 있습니다. 해당 값은 개인 계정 토큰이나 Cloud 관리자 권한이 아닙니다. 개발자의 개인 로그인 토큰·서비스 계정 개인키·GitHub 토큰을 앱에 넣어서는 안 됩니다.
- 외부 사용자 앱 인증 심사·실계정 동기화는 자동 테스트로 대체할 수 없습니다. 로그인 검증을 위해 타인의 계정이나 실제 캘린더에 자동 접근하지 않습니다.

## 과금 방지

TOMO는 자체 서버를 운영하거나 서버를 자동 생성하지 않습니다. Google API 호출은 공통 OAuth 프로젝트의 한도를 공유할 수 있습니다. 비용이 필요 없다면 해당 프로젝트의 결제 연결 및 유료 초과 사용을 활성화하지 않고 호출 한도를 관리하세요. 예산 알림만으로는 사용료가 자동 차단되지 않습니다. 앱은 결제 계정 폐쇄 여부나 다른 Cloud 자원의 상태를 판정하지 않습니다.
