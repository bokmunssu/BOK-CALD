# Google Tasks 연동 (2.3.1)

할 일 위젯 또는 설정 메뉴의 **Google Tasks → Google 계정으로 로그인 → 목록 선택 → 지금 동기화**를 사용합니다. 일반 사용자는 API 키나 클라이언트 ID를 발급하지 않습니다. 캘린더와 같은 배포용 데스크톱 OAuth 등록 정보를 사용하지만, 할 일은 별도 로그인을 통해 필요한 Tasks 권한만 요청합니다. 토큰은 운영체제 암호화 저장소로 보호하며 캘린더와 할 일의 로컬 연결 상태는 별도로 보관합니다.

제목·기한 날짜·완료 상태·삭제를 양방향 동기화합니다. 자동 동기화는 선택한 목록 또는 **전체 목록**에 대해 1분마다 수행합니다. 전체 동기화는 계정의 모든 목록을 먼저 조회하여 목록 이동을 삭제로 오인하지 않도록 합니다.

할 일 카드의 기존 태그 자리는 **목록 선택**으로 바뀌었습니다. 새 할 일을 추가할 때 대상 목록을 선택하고, 기존 항목의 목록을 바꾸면 다음 수동/자동 동기화에서 Google의 목록 이동 API로 옮깁니다. 목록별 보기도 지원합니다. 단일 목록 모드에서도 사용자가 명시적으로 선택한 대상 목록의 이동/추가는 처리합니다. 전체 모드에서 미지정 할 일은 이전에 선택한 기본 목록(없으면 첫 목록)에 추가됩니다. 다른 계정의 기존 연결 항목은 새 계정 목록을 명시적으로 선택하기 전에는 업로드하지 않습니다.

중요 표시는 Google Tasks 앱에 존재하지만 **공식 API에는 별표/중요 필드가 없어 읽기·쓰기 동기화를 지원하지 않습니다.** TOMO의 별표는 로컬 전용이며 Google의 별표를 덮어쓰지 않습니다. 이전 태그 데이터는 보존하고 편집 UI만 제거합니다. API는 기한의 시간과 반복 규칙을 제공하지 않습니다. Google의 메모·하위 할 일 정보를 TOMO에서 편집하지 않으며 기존 원격 메모는 제목/완료 변경으로 덮어쓰지 않습니다. Google은 반복 할 일의 목록 간 이동을 제한하므로 이 경우 오류를 표시하고 원본을 보존합니다.

Microsoft To Do 화면과 자동 동기화를 대체합니다. 기존 로컬 할 일과 이전 연결 정보는 삭제하지 않으며, 선택한 Google 목록으로 기존 로컬 할 일을 추가할 수 있습니다. Microsoft 서버의 항목을 자동으로 삭제하거나 이동하지 않습니다. 연결을 해제해도 내려받은 로컬 할 일은 유지합니다.

같은 항목을 양쪽에서 수정하면 로컬 사본을 남깁니다. 저장 중 입력한 내용과 중요 표시를 덮어쓰지 않습니다. Google Tasks는 비공개 사용자 메타데이터/멱등 생성 키를 제공하지 않아, 새 항목 추가 또는 목록 이동 응답이 유실되면 무조건 반복하지 않고 중단합니다. Google Tasks 웹에서 원본/대상 목록을 확인한 뒤 연결 화면의 **변경 결과 확인 후 재시도**를 사용합니다. 확인되지 않은 항목은 다시 추가할 수 있다는 안내를 확인하고 중복을 정리해야 합니다. 외부 앱의 목록 이동 시 ID가 유지된 항목은 전체 동기화에서 기존 로컬 항목과 연결합니다. 다른 ID로 재생성된 항목은 새로운 할 일로 처리될 수 있습니다.

## 배포자 설정

1. 기존 Google Cloud 프로젝트에서 **Google Tasks API**를 사용 설정합니다. 프로젝트 `firm-buffer-488015-s0`는 2026-10-05 콘솔에서 사용 설정됨을 확인했습니다.
2. Google Auth Platform의 데이터 액세스/인증 신청에 `https://www.googleapis.com/auth/tasks`를 추가합니다. 캘린더 로그인은 Calendar 권한, Tasks 로그인은 Tasks 권한과 이메일/openid를 각각 요청합니다. 기존 데스크톱 클라이언트를 재사용하므로 새 JSON 발급은 필요하지 않습니다.
3. Testing 상태라면 사용할 Google 계정을 테스트 사용자로 등록합니다. API 활성화만으로 Google 앱 인증/외부 사용자 승인이 끝나는 것은 아닙니다.
4. 빌드/CI의 공통 OAuth 등록 정보를 유지합니다. Google 계정 비밀번호·개인 로그인 토큰을 릴리즈에 넣지 않습니다.
5. 앱에서 Tasks 로그인을 한 번 진행하여 새 권한에 동의합니다. 실계정 목록 조회·추가·완료·기한 변경·삭제·재로그인을 별도로 확인합니다.

새 기능의 동기화는 모의 API로 검증합니다. **실계정 성공 및 Google 검토 승인을 의미하지 않습니다.** 소유 도메인과 검증 동영상 등 미완료 조건은 [Google 인증 신청 안내](GOOGLE_VERIFICATION.md)를 확인하세요.

## 기간 일정 표시

상단의 **기간 일정: 날짜별 / 이어서**를 선택합니다. 기본값은 기존 날짜별 표시입니다. 이어서는 월·주 보기에서 여러 날짜를 가로지르는 하나의 막대를 사용합니다. 겹치는 일정은 별도 줄로 배치하고 주 경계에서는 양 끝 화살표로 이어짐을 표시합니다. 일 보기와 Google에 저장되는 일정 날짜/반복 규칙은 변경하지 않습니다. 표시 선택은 재실행 후에도 유지됩니다.

## 공휴일·음력·카테고리

Google 제공 공휴일 구독은 일정/카테고리 가져오기에서 제외합니다. 이전에 가져온 공휴일 항목도 로컬 일정 화면에서 숨깁니다. Google 서버의 공휴일 구독이나 사용자가 직접 만든 같은 제목의 일정은 삭제하지 않습니다. 한국 공휴일 표시는 기존 **공휴일** 설정으로 관리합니다.

**음력** 체크는 월/주/일 달력의 음력 날짜 표시를 전환합니다. 일정과 D-DAY 날짜 입력의 **음력**에서 연·월·일·윤달을 선택하면 양력 날짜로 변환해 저장하고 입력 기준도 보관합니다. 지원 범위는 한국 음력 변환 라이브러리의 1000–2050년 데이터이며, 유효하지 않은 윤달은 저장할 수 없습니다. **반복 일정은 여전히 양력 기준**이며 매년 음력 생일을 자동 계산하는 반복 규칙은 지원하지 않습니다.

Google 연결 상태에서 카테고리를 추가할 때 **내 Google 캘린더와 연결**이 기본 선택됩니다. 생성 후 목록 캐시를 갱신하고 중복 요청을 합칩니다. 연결된 일정을 수정해 카테고리를 바꾸면, 자동 동기화가 켜져 있을 때 대상 Google 캘린더로 이동한 뒤 내용을 수정합니다. 대상 캘린더 쓰기 권한이 없거나 Google이 이동을 허용하지 않는 일정 유형이면 오류를 표시하고 로컬 수정은 유지합니다.
